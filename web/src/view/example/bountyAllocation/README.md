# 战队奖金分配页面使用说明

## 功能概述

战队奖金分配页面用于管理**战队内部奖金**分配给选手，采用分步骤引导式操作流程，支持最多4名选手同时分配。

> **重要提示**: 本页面专门用于分配**战队奖金**，与**赏金池奖金**（通过击杀等游戏行为获取）独立管理，两种奖金来源和分配机制完全独立。

## 奖金类型区分

### 战队奖金
- 来源：战队获得的比赛奖金、赞助商奖金等
- 管理方式：通过本页面进行分配
- 特点：可自由分配给战队内的选手

### 赏金池奖金
- 来源：游戏内击杀、被击杀、复活等行为产生的奖金
- 管理方式：通过赏金池管理页面操作
- 特点：由系统根据游戏行为自动计算

## 页面结构

```
├── 页面标题区           # 显示页面标题和类型标识
├── 步骤指引            # 四步引导：选择战队 → 选择选手 → 分配奖金 → 确认提交
├── 步骤内容区           # 根据当前步骤显示不同内容
│   ├── 步骤1：选择战队  # 展示战队列表和各自奖金总额
│   ├── 步骤2：选择选手  # 展示选手列表，支持搜索
│   ├── 步骤3：分配奖金  # 输入分配金额，支持多种方式
│   └── 步骤4：确认提交  # 查看分配汇总，确认提交
└── 确认弹窗            # 提交前的二次确认
```

## 核心功能

### 1. 步骤引导流程

页面采用四步引导流程：
1. **选择战队** - 选择要分配奖金的战队
2. **选择选手** - 从战队中选择参赛选手（最多4名）
3. **分配奖金** - 为每位选手分配金额
4. **确认提交** - 确认分配方案并提交

每个步骤都有清晰的操作指引和进度显示。

### 2. 战队选择（步骤1）

- **自动加载**: 进入页面后自动加载战队列表
- **实时展示**: 每个战队卡片显示战队名称和当前奖金总额
- **选择反馈**: 选中战队高亮显示，右侧显示对勾标识
- **刷新功能**: 提供刷新按钮获取最新战队数据
- **数据完整**: 显示的奖金总额实时反映战队当前可用奖金

### 3. 选手选择（步骤2）

- **自动加载**: 选择战队后自动加载该战队下的选手列表
- **搜索功能**: 支持按选手姓名快速搜索过滤
- **多选支持**: 最多选择4名选手，支持添加/移除操作
- **已选展示**: 顶部显示已选选手标签，可快速移除
- **禁用提示**: 已满4人后，其余选手卡片显示禁用状态

### 4. 奖金分配（步骤3）

#### 奖金信息栏
- 战队名称
- 可用战队奖金
- 已分配金额
- 剩余金额（超支时红色警告）
- 分配进度百分比

#### 分配方式

##### 方式一：直接输入金额
- 在"分配金额"输入框中直接输入数值
- 支持两位小数精度
- 自动校验金额合法性和总额限制

##### 方式二：滑块控制
- 使用滑块调整分配比例（0-100%）
- 自动计算对应金额
- 滑块禁用时表示战队奖金为空

##### 方式三：快捷分配按钮
- 提供25%、33%、50%三个快捷比例按钮
- 点击后自动计算并填入对应金额

##### 方式四：平均分配
- 点击"平均分配"按钮
- 自动将奖金平均分配给所有已选选手

### 5. 确认提交（步骤4）

- **分配汇总**: 清晰展示战队名称、分配总额和每位选手的分配明细
- **比例显示**: 每位选手显示分配金额和占比
- **警告提示**: 明确提示提交后不可撤销
- **保存草稿**: 提供草稿保存功能，方便后续继续编辑

### 6. 实时校验

- **金额校验**: 输入非数字或负数时自动归零
- **总额限制**: 已分配金额超过可用战队奖金总额时显示错误提示
- **选手数量限制**: 最多支持4名选手，超出后禁用添加功能

## 使用流程

### 标准分配流程

1. **进入页面**: 系统自动加载战队列表，显示各战队奖金总额
2. **选择战队**: 点击目标战队卡片，进入步骤2
3. **选择选手**: 点击选手卡片进行选择（可多选），支持搜索
4. **分配金额**: 使用输入框、滑块或快捷按钮分配金额
5. **检查汇总**: 进入步骤4查看分配明细
6. **确认提交**: 点击确认提交，完成分配

### 平均分配流程

1. 选择战队和选手
2. 在分配页面点击"平均分配"按钮
3. 系统自动计算平均金额填入各选手
4. 如需调整，可手动修改具体金额
5. 确认提交

## 技术规范

### 前端技术栈
- Vue 3 + Composition API
- Element Plus UI组件库
- SCSS样式预处理

### API接口

| 接口名称 | 方法 | 说明 | 来源 |
|---------|------|------|------|
| `/team/teamList` | GET | 获取战队列表 | team.js |
| `/player/playerList` | GET | 获取选手列表 | player.js |
| `/bountyAllocation/teamBonus` | GET | 获取战队奖金信息 | bountyAllocation.js |
| `/bountyAllocation/submit` | POST | 提交奖金分配 | bountyAllocation.js |
| `/bountyAllocation/saveDraft` | POST | 保存分配草稿 | bountyAllocation.js |

### 数据结构

**战队对象**:
```json
{
  "ID": "team_id",
  "teamName": "战队名称",
  "teamBounty": 1000.00
}
```

**选手对象**:
```json
{
  "ID": "player_id",
  "playerName": "选手姓名",
  "playerBounty": 100.00
}
```

**分配提交数据**:
```json
{
  "teamId": "team_id",
  "players": [
    { "playerId": "player_id", "name": "选手A", "amount": 500.00 },
    { "playerId": "player_id", "name": "选手B", "amount": 300.00 }
  ]
}
```

## 安全要求

1. **敏感数据脱敏**: 金额显示格式化，隐藏敏感信息
2. **操作权限控制**: 提交操作需用户确认，防止误操作
3. **金额篡改防护**: 前端校验配合后端验证，防止恶意修改
4. **奖金类型隔离**: 战队奖金与赏金池奖金分别管理，防止混淆

## 响应式适配

- **桌面端**: 完整功能展示，多列卡片布局
- **平板端**: 双列卡片布局，调整间距
- **移动端**: 单列布局，垂直排列操作按钮

## 用户体验优化

1. **加载反馈**: 数据加载时显示加载动画和提示文字
2. **选择反馈**: 操作后立即显示选中状态
3. **错误提示**: 输入错误时即时显示错误信息
4. **步骤动画**: 步骤切换时使用淡入动画
5. **确认机制**: 提交前二次确认，防止误操作

## 注意事项

1. **奖金类型区分**: 本页面仅用于战队奖金分配，赏金池奖金需通过其他页面操作
2. 提交分配后将从战队奖金扣除相应金额，此操作不可撤销
3. 草稿状态的记录可以恢复继续编辑
4. 已完成的记录仅可查看详情，不可修改
5. 分配金额总和不能超过可用战队奖金总额
6. 每位选手必须填写姓名才能提交
